# 26.11.0 — Engine bump to GroupDocs.Metadata 26.11.0 + write_metadata mode fix

## What changed

### Engine: GroupDocs.Metadata 26.6.0 → 26.11.0
- `build/dependencies.props`: `<GroupDocsMetadata>` bumped; package CalVer **26.9.0 → 26.11.0**
  (both `.mcp/server.json` version fields, README/`llms.txt` pins, regenerated `install/generated/`).
- Under `net10.0` NuGet now resolves **`GroupDocs.Metadata.Net100`** (native .NET 10 target added
  in 26.11) instead of the previous Net80 fallback.
- Inherits from 26.8+: archive formats AAR / GZIP / BZ2 / XZ / ZSTD, and the transitive
  `GroupDocs.CrossPlatform.NativeAssets` package (candidate fix for PPTX/PPT on Linux/Docker — M1).
- Inherits security fixes: System.Text.Json 6.0.10, System.Security.Cryptography.Pkcs CVE bumps;
  unsupported binary files no longer mis-open as MP3.

### Other dependency bumps
- `Microsoft.Extensions.Hosting` **10.0.5 → 10.0.15**.
- `GroupDocs.Mcp.Core` / `ModelContextProtocol` unchanged (Core already at latest 26.9.0; MCP SDK
  stays on 1.1.0 — a 2.x bump needs a coordinated Core release).

### Fix M2: `write_metadata` mode handling
- Unknown `mode` values are rejected with a clear error (`Use 'set' or 'add'`), instead of silently
  treating everything other than `add` as `set`.
- When `mode:add` changes 0 fields, the response explains that add only works for list-capable
  fields (e.g. Keywords), instead of the misleading "not applicable" message used for `set`.

### Pack size: strip exotic RIDs
- A full publish with CrossPlatform.NativeAssets + multi-RID Skia lands a **~307 MB** nupkg
  (over NuGet.org's 250 MB limit). After Publish we now also drop exotic RID folders
  (`linux-musl-*`, `linux-loongarch64`, `linux-riscv64`, `linux-arm`, `linux-x86`, `win-x86`)
  and the 32-bit Windows Slides native, keeping win / linux / osx (+ x64 / arm64). Trimmed
  pack is ~240 MB.

## Why
Stay on the current engine (native net10 + CVE fixes + CrossPlatform natives) and stop sending
agents the wrong way on failed `mode:add` / typo modes.

## Migration / impact
- Drop-in for callers using `mode` of `set` / `add` / omitted.
- Callers that previously passed a typo mode and relied on silent `set` behaviour will now get an
  error string starting with `Metadata write failed for`.
- `dnx` / global-tool on musl (Alpine), loongarch, riscv, or 32-bit Linux/Windows no longer ship
  matching native assets; use Docker (glibc amd64/arm64) or a supported RID host instead.
